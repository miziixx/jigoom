# 나의 사주 선생님 — 텔레그램 봇

> 📄 **기능 전체 명세: [`../docs/telegram-bot-features.md`](../docs/telegram-bot-features.md)** — 타로·맥락 라우터·의도 목록·상태 모델·안전 원칙까지 코드 기준 상세 정리.

만세력 기반으로 정확히 계산한 사주 데이터(원국·십성·지장간·통근/투출·신강신약·격국·신살·대운/세운/월운·오늘 일진)를 근거로, Claude가 "왜 그런지"를 짚어가며 설명해주는 개인 사주 선생님 봇.

- 계산은 전부 기존 웹앱 엔진(`src/lib/saju.ts`, `src/lib/fortune.ts`)을 재사용 — AI가 간지를 지어내지 않고, 프로그램이 계산한 값만 근거로 해석합니다.
- 서머타임·표준시 경선(1954~1961 UTC+8:30)·출생지 경도 보정, 야자시/조자시, 음력·윤달까지 웹앱과 동일하게 처리됩니다.

## 두 가지 실행 방식

| | 웹훅 (프로덕션 권장) | 롱폴링 (로컬 개발/테스트용) |
|---|---|---|
| 어디서 실행 | Vercel 서버리스 함수(`api/telegram-webhook.ts`) | 아무 Node 프로세스(`bot/index.ts`) |
| 언제 실행 | 텔레그램 메시지가 올 때만 잠깐 실행 | 24시간 계속 켜져 있어야 함 |
| 비용 | 개인 사용량이면 사실상 0원 (Vercel 무료 한도 안) | 항상 켜진 서버 필요 → Railway 등에서 계속 과금 |
| 데이터 저장 | Upstash Redis(무료 티어) — 서버리스는 파일 저장이 안 됨 | 로컬 JSON 파일(`bot/data/users.json`) |
| 언제 쓰나 | **실제로 쓸 때는 이걸로** | 코드 고치고 바로 손으로 찔러볼 때 |

**둘을 동시에 켜두면 안 됩니다.** 텔레그램은 웹훅과 롱폴링을 동시에 지원하지 않아요 — 웹훅이 등록된 상태면 롱폴링(`getUpdates`)은 계속 에러만 냅니다.

---

## 준비물

1. **텔레그램 봇 토큰**: 텔레그램에서 [@BotFather](https://t.me/BotFather) → `/newbot` → 토큰 복사
2. **Anthropic API 키**: console.anthropic.com (이 저장소의 웹앱이 이미 Vercel에 배포돼 있다면 `ANTHROPIC_API_KEY`는 보통 이미 설정돼 있음)
3. **Upstash Redis** (웹훅용, 무료): [upstash.com](https://upstash.com) 가입 → **Create Database** → Region은 아무거나(가까운 곳) → 생성 후 **REST API** 섹션에서 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` 복사

## 웹훅 등록 (Vercel — 프로덕션)

이 봇은 이미 Vercel에 배포돼 있는 `saju-tarot-chatbot` 웹앱과 같은 프로젝트에서 서버리스 함수로 같이 돕니다. 별도 서버가 필요 없습니다.

### 1) Vercel 환경변수 등록
Vercel 대시보드 → 이 프로젝트 → **Settings → Environment Variables**에 추가:

| 변수 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | BotFather 토큰 |
| `TELEGRAM_WEBHOOK_SECRET` | 아무 랜덤 문자열 직접 생성 (예: `openssl rand -hex 20`) — 아무나 웹훅 URL을 알아도 위조 요청을 못 넣게 막는 값 |
| `UPSTASH_REDIS_REST_URL` | Upstash 대시보드에서 복사 |
| `UPSTASH_REDIS_REST_TOKEN` | Upstash 대시보드에서 복사 |
| `TELEGRAM_ALLOWED_USER_IDS` | 내 텔레그램 ID (권장 — [@userinfobot](https://t.me/userinfobot)으로 확인) |
| `BOT_MODEL` | (선택) 기본 `claude-opus-4-8`. 비용 아끼려면 `claude-sonnet-5` |
| `ANTHROPIC_API_KEY` | 이미 설정돼 있으면 그대로 두면 됨 |

등록 후 **재배포**(Redeploy)해서 반영하세요.

### 2) 텔레그램에 웹훅 URL 등록
터미널에서 딱 한 번만 실행하면 됩니다 (본인 값으로 바꿔서):

```bash
curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -d "url=https://<내-vercel-도메인>/api/telegram-webhook" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```

성공하면 `{"ok":true,"result":true,"description":"Webhook was set"}` 가 뜹니다.

확인:
```bash
curl "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getWebhookInfo"
```

되돌리고 싶으면(예: 다시 로컬 롱폴링으로 테스트하고 싶을 때):
```bash
curl "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/deleteWebhook"
```

### 3) 테스트
텔레그램에서 `/start` 보내보기. 안 되면 Vercel 대시보드 → **Deployments → 최근 배포 → Functions → telegram-webhook** 로그 확인.

### 4) 레일웨이에서 옮겨오는 중이라면 — 꼭 레일웨이 서비스를 지우세요
웹훅이 정상 동작하는 걸 확인했으면, Railway 프로젝트로 가서 **그 서비스를 삭제(또는 최소한 중지)**하세요. 안 지우면:
- 롱폴링 프로세스가 계속 돌면서 웹훅과 충돌해 에러 로그만 반복해서 남기고
- **레일웨이 요금도 계속 그대로 나갑니다** — 웹훅으로 옮기는 목적 자체가 이 비용을 없애는 거예요.

## 로컬 개발/테스트 (롱폴링)

코드를 고치고 배포 전에 손으로 빠르게 찔러보고 싶을 때만 씁니다.

```bash
cd saju-tarot-chatbot
npm install

# 웹훅이 등록돼 있으면 먼저 해제 (안 그러면 getUpdates가 계속 실패함)
curl "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/deleteWebhook"

TELEGRAM_BOT_TOKEN="123456:ABC-..." \
ANTHROPIC_API_KEY="sk-ant-..." \
npm run bot
```

로컬 실행은 `bot/data/users.json`(파일)에 저장하므로 Upstash 없이도 됩니다. 테스트가 끝나면 다시 웹훅을 등록해서 프로덕션으로 돌려놓으세요.

## 응답 길이 제어 — 자연어 힌트

질문에 특정 단어를 포함시켜 답변 길이를 실시간으로 조절할 수 있습니다. 환경변수 `BOT_VERBOSITY`보다 우선합니다.

### 짧게 답하기 (brief — 4000 토큰)
질문에 다음 중 하나를 포함:
- `"나 왜 신약사주야? 짧게"`
- `"성격 간단히 알려줘"`
- `"요약해서 설명해"`
- `"핵심만"`

### 자세히 답하기 (detailed — 12000 토큰)
질문에 다음 중 하나를 포함:
- `"오늘 일진 길게 풀어줘"`
- `"궁합을 자세히 봐줄래"`
- `"깊게 설명해"`
- `"전부 알려줘"`

### 기본값으로 돌아가기 (normal — 8000 토큰)
질문에 다음 중 하나를 포함:
- `"일반적으로 설명해"`
- `"다시 정상 길이로"`

**예시:**
```
사용자: "내 신강신약이 뭔지 짧게 알려줘"
→ 봇은 자동으로 짧은 답변(4000 토큰)으로 응답하고, 힌트 단어 "짧게"는 질문에서 제거됨

사용자: "3월 운세를 자세히 봐줄 수 있어?"
→ 자세한 답변(12000 토큰)으로 응답
```

## 응답 스트리밍

봇의 답변이 생성되는 동안 실시간으로 Telegram에 반영됩니다. 예전처럼 다 만들어질 때까지 타이핑 표시만 보는 게 아니라, 답이 점점 채워지는 걸 볼 수 있어 체감 속도가 훨씬 빠릅니다.

- 생성 중에는 첫 메시지 하나를 `editMessageText`로 계속 갱신하고(일반 텍스트), 다 끝나면 최종본을 마크다운으로 확정 표시합니다.
- 웹훅·롱폴링 두 모드 모두 동일하게 동작합니다.
- 편집 간격은 rate limit 여유를 위해 최소 1.2초로 제한하며, 편집이 실패해도(예: 일시적 429) 최종 표시는 항상 보장됩니다.

## 사용법

1. `/start` → 안내
2. 생년월일시 등록 (한 줄, 형식 자유 — 완전 자연어도 됩니다):
   - `1993-03-15 14:30 여 서울`
   - `음력 1990년 5월 2일 07시 20분 남 부산`
   - `1988.7.15 시간모름 남`
   - `95년 8월 23일남자 성격좀 봐줘, 근데 시간 몰라` — 두 자리 연도·붙여쓴 성별·"시간 몰라"까지 알아서 읽고, **등록과 동시에 그 질문에 바로 답합니다**
2-1. **만세력에서 뽑은 사주팔자(여덟 글자)를 그대로 붙여넣어도 됩니다** — 생년월일시를 몰라도, 이미 아는 팔자로 바로 등록/해석돼요:
   - `경오 무자 임술 갑진`
   - `연주 경오 월주 무자 일주 임술 시주 갑진`
   - `경오년 무자월 임술일 갑진시` / 역순 `정묘시 임술일 무자월 경오년` 도 단위(년월일시) 기준으로 정확히 읽음
   - `경오 무자 임술 시간모름` (시주 모르면 생략/시간모름)
   - `경오 무자 임술 갑진 여자 나 왜 신약사주야?` 처럼 팔자+질문을 한 줄로 보내면 등록과 동시에 답합니다
   - 한자(`庚午 戊子 壬戌 甲辰`)도 자동으로 한글로 바꿔 읽어요
   - 🎯 **팔자를 넣으면 실제 생년월일을 되짚어줍니다.** 연·월·일주(가능하면 시주까지) 간지로 "이건 실제로 1990년 12월 23일이에요"처럼 날짜를 찾아내고, **그 날짜로 대운까지 계산**해요.
     - 같은 간지는 60년마다 반복돼서(예: 1924·1984), 사람 수명 안에서 **가장 최근(가장 어린) 연도를 자동 추측**하고 다른 후보도 알려줍니다. 다른 연도면 생년월일시로 알려주세요.
     - 성별을 안 주면 대운은 남성 기준으로 잡고 안내해요(여성이면 팔자 뒤에 `여`를 붙여 다시).
     - 날짜를 못 되짚으면(불가능한 조합 등) 팔자 그대로 해석해요 — 이때는 대운이 빠집니다.
   - ⚠️ 팔자로 사주를 세우려면 **최소 연·월·일주**가 필요해요. `갑자년 정축월`처럼 연·월주만 주면 '나(일간)'가 없어 사주가 안 세워집니다 — 일주까지 넣어주세요.
3. 그냥 물어보기:
   - "나 왜 신약사주야?"
   - "오늘 일진이 왜 이렇게 흘러가?"
   - "내 격국이 왜 그렇게 잡히는지 설명해줘"
   - "이번 달 흐름에서 조심할 건?"
   - "지장간은 왜 그렇게 배당되는 거야?" (내 사주와 무관한 이론 자체 질문도 답해줌)
4. `/궁합` 으로 상대와의 궁합 보기 — 상대 생년월일시(+관계)를 한 줄 더 보내면 두 사주를 맞대 풀어줌
5. `/퀴즈` 로 지금까지 배운 개념을 문제로 복습 — 문제만 먼저 오고, 답을 보내면 채점해줌
6. **타로** — 명령어 없이 그냥 자연어로. 사주 등록도 필요 없어요:
   - `"타로로 이번 연애 어떻게 흘러갈지 봐줘"` → 관계 스프레드로 자동
   - `"이직할까 말까 타로로 봐줘"` → 두 선택지 비교, `"이번 달 흐름 봐줘"` → 한 달 5장, `"카드 한 장만"` → 핵심 1장, `"제대로 깊게"` → 켈틱크로스 10장
   - 카드는 프로그램이 78장 덱에서 무작위로 뽑고(각 카드 50% 역방향), 상징·원소 조합(엘리멘탈 디그니티)까지 계산해 근거로 실어 해석합니다 — 웹앱 타로 엔진과 동일.
   - 뽑은 뒤 **`"그 카드 무슨 뜻이야?"`, `"한 장 더 뽑아줘"`** 처럼 이어서 물으면, 방금 뽑은 카드를 그대로 근거로 이어 풀어줍니다(맥락 유지).
   - `/타로` 만 치면 안내, `/타로 <질문>` 이면 바로 뽑아요.

답변은 항상 "왜 그런지" 원리부터 설명하고, 대화 맥락을 보고 이미 아는 용어는 다시 안 풀어주면서 자연스럽게 심화 질문에도 맞춰 답해줍니다. 답이 억지로 길지는 않고, 이해에 필요한 만큼만 씁니다.

입고/개고(진술축미 창고), 궁합, 점성술, 타로까지 웹앱 계산 엔진에서 뽑은 근거를 그대로 실어 해석합니다.

### 맥락 인지 라우팅 (100% 자연어)

명령어를 몰라도 사주·타로·점성술·비서(기획/글쓰기/판단/자기분석)를 전부 자연어로 씁니다. 자유 텍스트는 먼저
결정론적 키워드 분류(`intentDetector.ts`)를 거치는데, **보안 민감 동작(기억 저장/삭제/조회·보안 확인·대화
초기화)은 여기서 키워드로만 확정**되고 절대 LLM 판단에 맡기지 않습니다. 그 외 리딩/대화 계열은
`smartRouter.ts`가 **최근 대화 + 등록 상태(사주/생일/타로)까지 보고** 의도를 확정해, `"그럼 연애는?"`,
`"한 장 더"`, `"아까 그 카드"` 같은 맥락 의존 표현과 짧은 후속 질문을 알아듣습니다. 라우터는 빠른 모델
(기본 `claude-haiku-4-5-20251001`)로 돌고, 실패하거나 `BOT_SMART_ROUTER=0` 이면 키워드 결과로 안전하게
폴백합니다.
