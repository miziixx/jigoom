## 0. 공통 뼈대 — 거의 모든 기능이 이 5가지 기법 위에 서 있다

### ① 결정론 계산 엔진 (브라우저 안에서 전부 계산)
- **기법**: 만세력 라이브러리(`lunar-javascript`)로 음양력 변환·간지 산출 → 그 위에 십성·신살·격국·용신 등 명리 규칙을 순수 함수로 구현. **같은 생년월일이면 언제 어디서 돌려도 100% 같은 결과**(랜덤·AI 개입 없음). 테스트 815개(골든 케이스 46개 포함)가 이 계산을 잠근다.
- **핵심 파일**: `src/lib/saju.ts`(약 3,500줄 — 이 앱의 심장), `src/lib/ziwei.ts`(자미두수), `src/lib/astrology.ts`(서양점성술), `src/lib/tarot.ts`+`src/data/tarot*.ts`(타로 지식베이스)
- **개인정보 설계**: 계산이 브라우저에서 끝나므로 **생년월일 원본은 서버로 전송되지 않는다**. 서버에는 계산 결과(원국·운 흐름)와 성별·질문만 간다.

### ② AI 번역층 (계산 근거 → 사람 말)
- **기법**: 계산된 근거를 프롬프트에 실어 Claude API로 보내고, AI는 **판단을 새로 만들지 않고 "번역·문장화"만** 한다. 응답은 NDJSON 스트리밍(첫 글자부터 실시간 표시, 10초 간격 하트비트로 모바일 끊김 방지). 긴 리딩은 **병렬 분할 생성**(기본=앞/뒤 2분할, 고급=앞/중/뒤 3분할) 후 순서대로 합치고, 토큰 상한에 걸리면 **이어쓰기(continue)** 최대 6회로 완결을 보장한다. 화면 꺼짐 방지 WakeLock도 잡는다.
- **핵심 파일**: 서버 `api/reading.ts`, 프롬프트 `src/prompts/systemPrompt.ts`(1,300줄 — 섹션 구조·안전 규칙·용어 번역 지시 전부 여기), 클라이언트 스트리밍 `src/lib/readingApi.ts`, 상태 관리 `src/store/useReadingStore.ts`(zustand)

### ③ 검증 게이트 (AI가 근거 밖 소리를 하면 자동으로 잡는다)
- **기법**: AI 출력을 로컬 규칙으로 검사 → 걸리면 재작성 프롬프트로 1회 자동 교정(재작성도 스트리밍이라 화면이 안 멈춤) → 그래도 실패하면 결정론 fallback 문장으로 교체.
  - **기본 리딩**: JudgmentPack Evidence Gate — 계산 엔진이 먼저 "판단 팩"(도메인별 결론·확신도·반대 근거·허용 톤·금지 주장·근거 id)을 만들고, AI 출력이 팩을 벗어나면 잡는다. `src/lib/judgmentEngine.ts`·`judgmentGate.ts`·`judgmentValidation.ts`·`compactEvidence.ts`
  - **고급 리딩**: Content Gate — 단정 예언·공포 문구·고위험 조언 패턴 검사. 고급도 결론 방향은 기본과 같은 판단 팩에 **앵커링**돼 기본/고급 판단이 어긋나는 "신뢰 역전"을 막는다. `src/lib/readingValidation.ts`
- **안전 규칙**: 단정·공포·의료/법률/투자/결혼/퇴사 결론 금지, 전문용어는 본문 대신 "전문가 근거 보기"에만 — `CLAUDE.md`와 시스템 프롬프트에 이중으로 박혀 있다.

### ④ 캐시·저장 (전부 브라우저 localStorage — 서버 DB 없음)
- 같은 입력 재요청 시 AI를 다시 부르지 않는 결과 캐시(`resultCache.ts` — 키에 기간 버킷을 섞어 오늘 흐름은 일 단위, 나머지는 월 단위로 자동 만료, 최대 60개), 리딩 기록(`storage.ts`), 저장 명식 목록(`profile.ts`·`profileList.ts`), 프리미엄 플래그(`premium.ts`), 피드백(`feedback.ts`), 품질 신호(`readingDashboard.ts`).

### ⑤ API 보안 (공개 함수 남용 방어 — LLM 청구서 폭증 방지)
- Origin/Referer 검증 + 요청 크기 상한(200KB) + IP당 분당 40회 rate limit(Upstash Redis 있으면 정밀, 없으면 인메모리 폴백). `api/_security.ts`. 함수 시간 상한은 `vercel.json`(reading 300초, naming 120초, fortune 60초).

**결과 화면 — 위에서 아래 순서 (`ReadingResult.tsx` → `DefaultReadingTemplate.tsx`)**

9. **피드백**(`FeedbackBar.tsx`): 잘 맞음/일부/모르겠음/안 맞음 + 태그(너무 추상적·더 구체적·조언 좋음·설명 어려움). 동의 시 지난 피드백에서 **스타일 힌트**를 만들어 다음 리딩 프롬프트에 반영(개인화).

**사주 페이지에 얹힌 특수 모드**
- **자기 완전분석 (selfDeep, 프리미엄)**: 표준 섹션 대신 **전용 12블록**(핵심 기질→겉과 속→감정 구조→반복 패턴→관계 속의 나→일과 재능→돈과 현실감각→몸·생활 리듬→그림자·결핍·방어→현재 상태→행동 처방→확실/추정/확인 필요)으로 5,000~7,000자 통짜 생성. 근거 조립은 `selfDeep.ts`(그림자 도출 `deriveShadow`·분야별 신뢰도 계층 `buildConfidenceTiers`). 미구매자에겐 티저(`SelfDeepTeaser.tsx`)만.
- **토픽 심화 (topicDeep, 유료 소형 리포트)**: 연애/재물/직업/건강/올해 중 1개만 5섹션(한 줄 결론→지금 흐름→조심할 것→시기→행동, 1,000~2,500자)으로. **판단은 JudgmentPack이 이미 계산했으므로 문장화는 서버가 Haiku로 강제**(원가 통제 — 클라이언트가 모델을 못 정하게 서버에서 강제). `TopicDeepChat.tsx`, 결과는 세션에 저장 안 됨(컴포넌트 로컬).
- **과거 검증 (pastValidation)**: 사용자가 입력한 실제 과거 사건(연도+분야)을 그 해 계산 흐름과 대조해 "잘 맞음/일부/신호 약함" 판정 → AI에게 "맞은 분야는 자신 있게, 약한 분야는 조심스럽게" 지시. `pastValidation.ts`+`PastValidationPanel.tsx`. 무 API.
- **사주·자미두수 교차검증 (crossValidation)**: 같은 생년월일로 자미두수 명반+운한(대한·유년)을 브라우저에서 계산(`ziwei.ts` — iztro 라이브러리, 무거워서 동적 import)해 분야별 일치도를 대조 → AI의 "확신 세기"만 조절(강일치=또렷하게, 불일치="방식에 따라 갈릴 수 있다"). 원식 원본은 서버로 안 보내고 압축 리포트만.

### 🃏 타로 (`/tarot` — `TarotPage.tsx`)
- **무엇**: 질문 입력 → 스프레드 선택 → 셔플 → 카드 뽑기 → AI 해석.

- **셔플 4종**: 기본/리플/손끝으로 고르기/직접 고르기 — 방식이 근거 문장에 반영된다. 자동 뽑기와 직접 픽 모두 지원.
- **연출**: 셔플 애니메이션(`TarotShuffleStage`) → 펼쳐진 덱에서 직접 픽(`TarotPickBoard`) → 순차 공개(`TarotRevealStage`). 카드 그림은 **SVG 코드로 그림**(`viz/TarotCardArt.tsx` — 이미지 파일 없음, 저작권·용량 자유).
- **AI 근거**(`tarotSymbolism.ts`+`src/data/`): 카드마다 상징 원형·키워드·그림 단서·숫자/단계·슈트 의미·관계 적용·정/역 의미·자리 의미 + **코트 카드 16종 인물상**(`tarotCourtPersona.ts` — 인물상·성숙 단계·역방향 왜곡) + **마이너 56장 개별 심화**(현실 장면/그늘/조언, `tarotMinorDepth.ts`) + **전통 카드 조합 신호 51종**(`tarotCombos.ts` — 뽑힌 카드 안에 존재하는 쌍만 감지) + **원소 조합(엘리멘탈 디그니티)** 계산(인접 카드 강화/약화) + 정/역 비율·메이저 비율·반복 슈트·시작→마지막 흐름 축 진단. 이 전부가 프롬프트 근거로 들어가 "카드 이름만 읊는" 해석을 막는다.
- 순수 타로는 사주 섹션을 강요하지 않는 전용 5섹션(첫 점괘→질문 핵심→카드가 그리는 흐름→해야 할 것→마지막 점괘). 깊이 고급 시 '# 흐름을 가르는 지점' 추가(`TAROT_ADVANCED_ADDENDUM`).

### 🌅 오늘 카드 (`/tarot-today` — `TarotTodayPage.tsx`)
- **무엇**: 하루 한 장 카드 + 키워드·분위기·현실 조언.

### ☀️ 오늘 운세 (`/fortune` — `FortunePage.tsx`, 구 `/today`는 리다이렉트)
- **무엇**: 오늘 점수·총운·분야별 운세·시간대별 흐름·추천/피할 행동·행운 아이템·오늘의 카드.

### 💞 궁합 (`/compatibility` — `CompatibilityPage.tsx`)
- **무엇**: 두 사람 명식 → 관계 유형별(연인·배우자/부모·자식/형제·자매/가족/사장·직원/동료·동업자/친구) 궁합 리포트. 질문 넣으면 질문 답변 카드가 먼저.
- **기법**: 점수·분석은 **100% 결정론**(`computeCompatibility`, saju.ts 안 약 1,500줄) — 일간 관계, 용신 상호 보완, 조후(계절) 보완, 배우자궁(일지) 합충, 오행 보완, 감정/표현/책임/생활 리듬 세부 흐름, **역할 케미**(상대가 나를 어떻게 느끼는지), 교차 타이밍, 고전 보완까지. **대칭성(A,B 순서 바꿔도 동점)·0~100 범위 불변식이 테스트로 잠겨 있음.** 점수 하나로 환원하지 않는 것이 사용자 확정 원칙.
- **관계 보완 리포트**(`compatibilityRepairReport` — 룰 기반, API 비용 0): 왜 이런 흐름이 생기는지→갈등이 커지는 순서→회복법→나/상대/둘이 같이 조언→실제 대화 문장 예시→하지 않는 편이 좋은 반응→7일 조율 플랜. 점수가 낮을수록 보완 중심으로 더 자세히.
- **시각화**: 레이더 폴리곤(세부 흐름 N축, 점수 대신 생활 언어 tierWord)+게이지 목록+`ArcGauge`.
- **상대 완전분석 (personDeep, 프리미엄)**: 궁합 위에 얹는 심화 — 상대의 작동방식을 **전용 16블록**(핵심 기질/겉과 속/감정 구조/무엇을 원하나/좋아할 때/불안할 때/거절 방식/질투·집착/미련·식을 때/나에게 끌리는·부담인 지점/말행동 불일치/반복 관계 패턴/케미/다루는 법/확실·추정·확인 필요)으로 해부. **상대 행동 체크** 입력(연락 주도·온오프 갭·약속 주도 등)과 계산 성향을 대조해 "말과 행동이 맞는지"를 짚음. 근거 조립은 `personDeep.ts`, 티저는 `PersonDeepTeaser.tsx`.
