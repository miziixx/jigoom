# 인명용 한자 데이터 도입 검토

작성일: 2026-07-05

## 결론

현재 단계에서는 앱 내부에 인명용 한자 DB를 임의로 구축하지 않는다.

이유:

- 법적 등록 가능성은 최신 법령·예규·전자가족관계등록시스템 기준에 따라 확인되어야 한다.
- 공식 PDF/조회 화면은 확인했지만, 앱에 복제·가공해 넣을 수 있는 라이선스와 갱신 절차가 아직 확정되지 않았다.
- 한자 뜻, 자원오행, 획수, 인명용 여부를 AI가 임의 생성하면 법적·품질 리스크가 크다.

따라서 현재 앱은:

- 한글 이름의 발음오행
- 사용자가 직접 입력한 획수 기반 수리
- 사주 보완 기운
- 후보 비교
- AI 해석 리포트
- 공식 확인 안내

까지만 제공한다.

## 공식 확인한 근거

### 찾기쉬운 생활법령정보

확인 URL:

- https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=2&cciNo=1&cnpClsNo=2&csmSeq=1830

확인 내용:

- 자녀 이름에는 한글 또는 통상 사용되는 한자를 사용해야 한다.
- 인명용 한자의 범위는 교육부 한문교육용 기초한자와 가족관계의 등록 등에 관한 규칙 별표 1의 한자다.
- 인명용 한자가 아닌 한자가 이름에 포함된 경우, 가족관계등록부에는 이름이 한글로 기록될 수 있다.
- 부 또는 모 등과 같은 이름, 성을 제외한 이름자가 5자를 초과하는 경우 등 별도 제한이 있다.
- 생활법령정보 자체도 법적 효력을 갖는 유권해석이 아니며, 구체적 사안은 담당 기관 확인이 필요하다고 안내한다.

### 전자가족관계등록시스템

확인 URL:

- https://efamily.scourt.go.kr/cs/CsBltnWrtList.do?bltnbordId=0000010

확인 내용:

- 고객센터 메뉴에 `인명용 한자 조회`가 있다.
- 한자는 지정된 발음으로만 사용할 수 있다는 주의사항이 있다.
- 첫소리가 ㄴ 또는 ㄹ인 한자는 소리나는 바에 따라 ㅇ 또는 ㄴ으로 사용할 수 있다는 안내가 있다.
- 동자·속자·약자 및 일부 부수 변형은 조회되는 한자에 한해 사용할 수 있다는 안내가 있다.
- `인명용한자표 PDF파일(다운로드)` 항목이 있다.

## 앱에서 지켜야 할 원칙

1. `인명용 한자 사용 가능`을 앱이 단정하지 않는다.
2. `법적으로 등록 가능`이라고 표시하지 않는다.
3. 인명용 한자 DB를 넣기 전까지 한자 뜻, 자원오행, 획수는 자동 생성하지 않는다.
4. 한자 획수는 사용자가 직접 입력한 경우에만 수리 참고 자료로 계산한다.
5. 출생신고·개명 신청 전에는 전자가족관계등록시스템 또는 관할 기관에서 최종 확인하도록 안내한다.
6. 예명·상호·브랜드명은 상표, 도메인, SNS 계정, 기존 사용 여부 확인이 별도로 필요하다고 안내한다.

## 도입하려면 필요한 작업

### 1. 데이터 출처 확정

- 전자가족관계등록시스템 PDF를 앱 데이터로 복제·가공해도 되는지 확인
- 국가법령정보센터 별표 1 데이터 활용 가능성 확인
- 공공데이터포털 또는 공식 API 제공 여부 재확인
- 저작권/이용약관/갱신 의무 확인

### 2. 데이터 구조 설계

최소 필드:

- 한자
- 음
- 인명용 여부
- 지정 발음
- 사용 주의사항
- 출처
- 기준일

후속 확장 필드:

- 뜻
- 획수
- 자원오행
- 부수
- 변형자/동자/속자 관계

단, 후속 확장 필드는 반드시 신뢰 가능한 출처가 있을 때만 넣는다.

### 3. UI 구조

- 이름 후보 옆에 `공식 확인 필요` 배지 표시
- 한자 입력 시 `전자가족관계등록시스템에서 확인하기` 링크 제공
- 앱 내부 DB가 있을 때도 `최종 등록 가능 여부는 공식 시스템에서 확인` 안내 유지

### 4. 테스트

- 인명용 여부를 `확정` 문구로 표현하지 않는지 테스트
- 출처/기준일이 없는 한자 데이터가 표시되지 않게 테스트
- AI 프롬프트가 한자 뜻·자원오행을 임의 생성하지 않게 테스트

## 다음 추천 작업

1. 현재 앱의 법적 확인 안내에 공식 링크를 붙인다.
2. 인명용 한자 PDF/별표 1의 데이터 사용 가능성을 확인한다.
3. 가능하면 작은 샘플 DB를 수동으로 만들지 말고, 공식 출처 기반 자동 갱신 가능한 구조를 먼저 설계한다.
4. DB 도입 전에는 `한자 추천`이 아니라 `한자 확인 링크 제공` 수준으로 유지한다.
