## 3. 워크플로우 — 이대로만 한다

### 새 기능을 만들 때
1. 브랜치에서 작업 → `npm test` + `npm run build` 통과
2. 브랜치 푸시 → **Vercel 프리뷰 URL에서 실제 리딩 1회 확인** ← 이번 장애를 막았을 단계
3. 확인됐으면 main 병합 (main = 즉시 프로덕션 배포임을 항상 기억)
4. `record.md`에 한 줄 기록

### 버그가 났을 때
1. **Vercel 대시보드 → Functions 로그부터 본다** (추측 금지 — 이번에 로그 한 장이 오진 2번을 끝냈다)
2. 원인 확정 → 수정 → **같은 버그를 잡는 회귀 테스트 추가** (예: `serverEsmImports.test.ts`)
3. 프리뷰에서 확인 → main

### 세션을 시작할 때 (Claude에게 시킬 때 포함)
1. 이 문서(`roadmap.md`)의 태스크 트리에서 **가장 위의 미완료 항목**이 오늘 할 일
2. 끝나면: 체크박스 갱신 + worklog 한 줄 + 커밋/푸시
3. "뭐부터 하지?"라는 질문이 나오면 → 이 문서가 낡은 것이니 **이 문서부터 갱신**
