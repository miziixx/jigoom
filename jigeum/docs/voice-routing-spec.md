# 지금(jigeum) — 음성 라우팅 기능 기획서

> **한 줄 요약**: 전역 마이크 버튼 하나로 말하면 → 온디바이스 STT로 받아쓰고 → **AI 없이 규칙 엔진**으로 인텐트를 분류해 → 알맞은 입력 지점(A~J)에 자동으로 담아준다.
>
> **대상 문서**: 이 기획서는 Claude Code에게 그대로 넘겨 구현을 시작하기 위한 것이다. 5장(구현 순서)과 6장(파일 구조)이 실제 작업 지시에 해당한다.

---

## 0. 핵심 설계 결정 (이 3가지가 전체 난이도를 결정함)

| 결정 | 내용 | 이유 / 효과 |
|------|------|-------------|
| **AI 미사용** | LLM·클라우드 추론 없음. 온디바이스 STT + 순수 규칙 엔진만 | 오프라인 동작, 비용 0, 지연 없음, 결정적(같은 말=같은 결과). 대신 **규칙 사전과 파서를 우리가 직접 잘 만들어야 함** |
| **되묻지 않음** | 애매하면 사용자에게 질문하지 않고 **빠른담기(A)**로 보냄 | 흐름이 끊기지 않음. ADHD 배려 원칙(판단·마찰 최소화)과 일치 |
| **못 알아들으면 보류함** | 인텐트를 아예 못 잡으면 **원문 그대로 '보류함'에 저장** | 사용자의 말은 절대 버리지 않음. 나중에 정리 |

이 결정 덕분에 **"되묻기 UI"와 "확신도 대화 분기"가 통째로 사라진다.** 파이프라인이 한 방향으로 단순해짐.

---

## 1. 전체 파이프라인 (한 방향, 분기 없음)

```
[전역 마이크 탭]
      │
      ▼
① STT 받아쓰기        안드로이드 SpeechRecognizer, 한국어
      │  raw text + STT 신뢰도
      ▼
② 정규화(normalize)   공백/조사 정리, 숫자·시간 표현 표준화
      │  normalized text
      ▼
③ 날짜·시간 파싱      "내일 3시" → {date, time, durationMin} 추출 + 텍스트에서 제거
      │  time slots + 남은 텍스트
      ▼
④ 인텐트 분류(점수제)  키워드·패턴·시간단서로 각 인텐트 점수 → 최고점 선택
      │  intent + score
      ▼
⑤ 슬롯 추출           제목, 중요/긴급, 그룹명 등 인텐트별 슬롯 채움
      │
      ▼
⑥ 라우팅 & 실행       아래 3갈래 중 하나로 확정
      │
      ├─ 점수 ≥ 확정임계값        → 해당 입력지점(A~J)/이동/도움 으로 실행
      ├─ 점수 애매(후보 있음/낮음) → 빠른담기(A)
      └─ 매칭 0 (인텐트 못 잡음)   → 보류함
      │
      ▼
⑦ 확정 피드백 + 되돌리기   토스트/스낵바 "○○에 담았어요 [되돌리기]"
```

핵심은 **⑥의 세 갈래를 명확히 가르는 규칙**이다. 이게 이 기능의 심장이다.

---

## 2. 라우팅 규칙 — 세 갈래를 어떻게 가르나

점수제를 쓴다. 각 인텐트마다 0점에서 시작해 단서가 맞을 때마다 가점한다.

```
최고점 인텐트의 점수를 S, 2등과의 격차를 D 라고 할 때:

S == 0                        →  ③ 보류함        (아무 단서도 못 잡음 = 미인식)
S >= CONFIRM(=3) 그리고 D>=1  →  ① 확정 라우팅   (유력하고 경쟁자와 벌어짐)
그 외 (S 낮거나 D 애매)       →  ② 빠른담기(A)   (뭔가 있긴 한데 애매)
```

- **CONFIRM 임계값과 가중치는 상수로 빼서** 튜닝 가능하게 한다(초기값 위와 같이).
- "애매"의 정의를 코드로 못 박은 것이 포인트: **후보는 있으나 확신 부족** → A로. **후보 자체가 없음** → 보류함으로. 사용자 결정 그대로다.

### 2-1. 시간 단서가 주는 강한 가점
날짜·시각이 잡히면 그 자체가 강한 신호다.

| 잡힌 것 | 가점 대상 | 점수 |
|---------|-----------|------|
| 미래 날짜 + 시각 (예: 내일 3시) | 일정추가(C) | +3 |
| 미래 날짜만 (예: 금요일) | 일정추가(C) | +2, 할일추가(A)에도 +1 (마감일 후보) |
| 기간만 (예: 25분, 30분) | 집중(J) 또는 기록(D) | +2 (동사에 따라 갈림, 아래) |
| 과거 시제 (예: 방금/했어/끝냈어) | 기록(D) | +3 |

## 3. 인텐트 분류 규칙 (AI 대신 이걸로 판단)

### 3-1. 인텐트 목록과 라우팅 대상

| 인텐트 | 계열 | 라우팅 입력지점 | 뽑는 슬롯 |
|--------|------|-----------------|-----------|
| `schedule.add` | 추가 | C 일정 | 날짜·시각·제목·(반복·알림) |
| `todo.add` | 추가 | A 빠른담기 | 제목·(마감날짜) |
| `todo.matrix` | 추가 | B 매트릭스 | 제목·중요·긴급 |
| `log.now` | 추가 | D 지금기록 | 내용(현재 30분 블록) |
| `habit.add` | 추가 | E 습관 | 이름 |
| `habit.check` | 추가 | E 습관틱 | 대상 습관명 |
| `routine.add` | 추가 | F 루틴 | 그룹명·스텝 |
| `goal.add` | 추가 | G 목표 | 제목 |
| `goal.today` | 추가 | I 오늘의목표 | 텍스트 |
| `focus.start` | 추가 | J 포커스 | 분 |
| `nav.move` | 이동 | 해당 화면 전환 | 목적지 |
| `help.stuck` | 도움 | 막힘 시트 | — |
| `help.fortune` | 도움 | 드로어 02 운세 | — |

### 3-2. 키워드·패턴 사전 (규칙 엔진의 연료)

각 인텐트마다 **트리거 사전**을 만든다. 매칭되면 가점. 아래는 초기 사전(운영하며 늘림).

```yaml
# 동사/어미 신호 — 시제와 의도를 가른다
past_markers:   [했어, 했다, 끝냈어, 방금, 아까, 마쳤어, 했음]      # → log.now 강신호
future_markers: [할래, 하자, 해야, 예정, 잡아, 넣어줘, 만들어]      # → 추가형 신호

# 인텐트별 트리거
schedule.add:  [예약, 미팅, 약속, 회의, 모임, 병원, 치과]           # + 시간단서 필수급
todo.matrix:   [중요, 급해, 긴급, 당장, 오늘까지, 빨리]             # 중요/긴급 슬롯도 여기서
log.now:       [기록, 방금 ~했어 패턴]                              # past_markers 의존
habit.add:     [습관, 매일, 꾸준히]                                 # + "만들어/추가"
habit.check:   [했어 + 기존 습관명 일치]                            # 등록된 습관명 대조
routine.add:   [루틴, 아침루틴, 저녁루틴, 스텝, 추가]
goal.add:      [목표, 세울래, 하고싶어, 이루고싶어]
goal.today:    [오늘 목표, 오늘은]                                  # "오늘"이 목표에 붙음
focus.start:   [집중, 몰입, 타이머, ~분만]                          # + 기간단서
nav.move:      [보여줘, 열어줘, 가자, 이동, ~화면, 달력 보여줘]
help.stuck:    [막혔어, 못하겠어, 안돼, 하기싫어, 미루고싶어]
help.fortune:  [운세, 사주, 오늘 운, 별자리]
```

### 3-3. 충돌 해소 규칙 (겹칠 때 우선순위)

말은 종종 여러 신호를 동시에 갖는다. 아래 순서로 가점 후 **최고점**이 이긴다.

1. **시제가 최우선**: `past_markers`가 있으면 `log.now` / `habit.check`에 강가점(+3). 과거는 거의 항상 기록이다.
2. **시간+시각 조합**은 `schedule.add`로 강하게 끈다(+3). "내일 3시 치과" 류.
3. **중요/긴급 형용사**는 `todo.matrix`로(+3), 동시에 중요·긴급 슬롯을 채운다.
4. **기간(N분)+집중동사** → `focus.start`, **기간만 + 과거** → `log.now`.
5. **"오늘"+"목표"** 근접 → `goal.today` (일반 `goal.add`와 구분).
6. **이동/도움 동사**("보여줘/막혔어/운세")는 추가형과 안 겹치므로 독립 판정.

> 규칙이 다 빗나가 **S==0** 이면 → **보류함**. 후보는 떴지만 임계 미달이면 → **빠른담기(A)**.

## 4. 한국어 날짜·시간 파서 (이 기능의 두 번째 심장)

라이브러리 없이 규칙으로 직접 만든다. **파싱한 부분은 원문에서 잘라내** 남은 텍스트가 제목이 되게 한다.
(예: "내일 3시에 치과 예약" → 시간부 제거 → 제목 "치과 예약")

### 4-1. 날짜 표현
| 종류 | 예시 | 해석 |
|------|------|------|
| 상대일 | 오늘·내일·모레·글피·어제 | 기준일 ± N |
| 요일 | (이번주/다음주) 월~일 | 가장 가까운 미래 해당 요일, "다음주"면 +7 |
| 절대일 | N월 N일, N일 | 해당 월/일 (과거면 다음 해/달로 롤오버) |
| 며칠 뒤 | N일 뒤, N일 후 | 기준일 + N |

### 4-2. 시각 표현
| 종류 | 예시 | 해석 |
|------|------|------|
| 정시 | 3시, 세시 | HH:00 |
| 오전/오후 | 오전 9시, 오후 3시, 저녁 7시 | 12h→24h 변환 (오후/저녁/밤 = +12) |
| 분 | 3시 30분, 3시 반 | "반"=30분 |
| 애매시각 | 아침·점심·저녁·밤 | 기본 시각 매핑(아침=08, 점심=12, 저녁=18, 밤=21) — **설정으로 조정 가능하게** |

### 4-3. 기간 표현 (집중·기록용)
| 예시 | 해석 |
|------|------|
| 25분, 30분만, 한시간, 1시간 반 | durationMin 정수 |

### 4-4. 파서 출력 규격
```
TimeParseResult {
  date: DateTime?        // 없으면 null
  time: TimeOfDay?       // 없으면 null
  durationMin: int?      // 없으면 null
  isPast: bool           // 과거 시제/과거 날짜 여부 (인텐트 분류에 전달)
  matchedSpans: [range]  // 원문에서 잘라낼 구간
}
```

### 4-5. 한글 숫자 처리
"세시", "다섯시", "한시간" 같은 순우리말·한자어 수사를 아라비아 숫자로 매핑하는 작은 사전을 둔다(한~열, 하나~열, 스물 등). 범위는 시간/분 상식선(0~59)까지만.

## 5. 구현 순서 (Claude Code 커밋 단계) ★

기존 앱 방식(단계별 커밋)에 맞춰 10커밋으로 쪼갠다. **각 커밋은 독립 실행/테스트 가능해야 함.**

1. **`voice/` 모듈 뼈대 + 상수**
   `IntentType` enum, 가중치 상수(CONFIRM 등), 라우팅 결과 타입 정의. 로직 없이 골격만.
2. **STT 래퍼** (`SttService`)
   안드로이드 SpeechRecognizer 연동, 권한 요청, raw text + 신뢰도 반환. UI 없이 콜백만.
3. **정규화기** (`TextNormalizer`)
   공백·조사·숫자표기 정리. 단위 테스트 동봉.
4. **날짜·시간 파서** (`KoDateTimeParser`) — 4장 전체.
   테스트 문장 30개(아래 8장) 통과가 완료 조건.
5. **트리거 사전** (`intent_lexicon.dart` 혹은 asset yaml/json).
   3-2 사전을 데이터로 분리해 코드 수정 없이 늘리게.
6. **인텐트 분류기** (`IntentClassifier`) — 3장 점수제 + 3-3 충돌 해소.
   입력=정규화문+시간파싱결과, 출력=intent+score+2등격차.
7. **슬롯 추출기** (`SlotExtractor`)
   인텐트별 제목/중요·긴급/그룹명/분 등 채우기.
8. **라우터** (`VoiceRouter`) — 2장 세 갈래 결정 + 각 입력지점 호출.
   여기서 A~J 기존 생성 로직과 **보류함 저장**을 연결.
9. **보류함(Inbox)** 데이터·화면 (7장 데이터 모델).
   저장/목록/한 건을 다른 곳으로 재분류 이동.
10. **전역 마이크 UI + 확정 피드백/되돌리기**
    어느 화면에서나 뜨는 마이크 버튼(FAB 또는 마스트헤드), 스낵바 "○○에 담았어요 [되돌리기]", 되돌리기(마지막 생성 노드 삭제 + 원문 보류함 복원).

11. **개인화 자동학습** (`voice/learning/`) — 11장.
    되돌리기·재분류 로그를 빈도 통계로 세어 사용자 사전에 자동 반영. AI 아님, 카운터일 뿐.

> 4번과 6번이 가장 무겁다. 테스트 케이스부터 고정하고 구현할 것.
> 11번은 8~10번이 끝나 로그가 쌓이기 시작한 뒤 붙인다(마지막 커밋).

## 6. 제안 파일 구조

```
lib/features/voice/
├── voice_router.dart          # 최상위 진입: text → 실행 (8단계 오케스트레이션)
├── stt_service.dart           # SpeechRecognizer 래퍼
├── models/
│   ├── voice_result.dart      # intent, score, slots, routedTo
│   └── time_parse_result.dart
├── pipeline/
│   ├── text_normalizer.dart
│   ├── ko_datetime_parser.dart
│   ├── intent_classifier.dart
│   └── slot_extractor.dart
├── data/
│   └── intent_lexicon.dart    # 트리거 사전 (또는 assets/voice/lexicon.yaml 로드)
└── ui/
    ├── global_mic_button.dart
    └── voice_feedback.dart     # 스낵바 + 되돌리기

lib/features/inbox/            # 보류함 (신규)
├── inbox_repository.dart
├── inbox_screen.dart
└── inbox_item.dart
```

기존 A~J 생성 로직(할일/일정/습관 등 repository·service)은 **재사용**한다. voice_router는 그것들을 호출만 한다 — 음성용 별도 저장 경로를 만들지 않는다.

## 7. 데이터 모델 추가 (기존 모델은 그대로)

새로 필요한 건 **보류함**뿐이다.

```
InboxItem {
  id
  rawText        // 사용자가 말한 원문 그대로
  createdAt
  sttConfidence  // 참고용
  status         // pending / reclassified / dismissed
}
```

- 나머지(Node·Schedule·Habit·Routine·TimeBlock·FocusSession)는 **기존 것을 그대로 사용**. 음성은 입력 수단일 뿐이다.
- 되돌리기용으로 "마지막 음성 실행" 1건(생성된 엔티티 참조 + 원문)을 임시 보관.

## 8. 테스트 문장 세트 (완료 판정 기준) ★

Claude Code가 4·6번 커밋을 끝냈다고 하려면 아래가 기대대로 라우팅돼야 한다.

| 말한 문장 | 기대 인텐트 | 기대 라우팅 | 뽑힌 슬롯 |
|-----------|-------------|-------------|-----------|
| 내일 3시에 치과 예약 | schedule.add | C 일정 | date=내일, time=15:00, 제목="치과" |
| 금요일에 장보기 | schedule.add(약) / todo | C 또는 A | date=금요일 |

## 9. UX 세부

- **진입점**: 전역 마이크 버튼 1개. 어느 화면에서나 접근(플로팅 또는 마스트헤드 고정). 길게 눌러 말하기 / 탭 후 말하기 중 택1(권장: 탭→듣는 중 표시→자동 종료).
- **확정 피드백**: 실행 직후 스낵바 — `"매트릭스 Q1에 담았어요"` + `[되돌리기]`. 3~4초.
- **되돌리기**: 생성 엔티티 삭제 + 원문을 보류함으로 되돌림(사용자가 다시 시도 가능).
- **보류함 뱃지**: 쌓인 개수를 어딘가(전체 탭 또는 드로어)에 작게 표시해 방치되지 않게.
- **방해금지 존중**: quietMode 중엔 음성 실행돼도 알림/소리 없이 조용히 담기.

## 11. 정확도 극대화 전략 ★ (완벽에 근접시키는 레버)

> **전제 전환**: 규칙만으로 100%는 구조적으로 불가능하다(STT가 "치과"를 "치가"로 받으면 뒷단이 완벽해도 틀림). 목표는 **"절대 안 틀림"이 아니라 "틀려도 1탭으로 고쳐지고, 그 교정이 다음번 자동 반영"**. 아래 5개가 그걸 만든다.

### 11-1. 개인화 자동학습 (AI 아님, 빈도 통계)
- 되돌리기·재분류가 일어날 때 `(정규화 키워드 → 최종 착지 인텐트)`를 카운트.
- 같은 표현이 **N회(기본 3회)** 같은 곳으로 교정되면 → 사용자 사전에 자동 등록(+2 가점).
- 예: "장보기"를 세 번 A로 옮기면, 4번째부터 "장보기"는 A로 확정. 말투에 앱이 맞춰간다.
- 저장은 `UserLexiconEntry { key, intent, count, lastUsed }`. 순수 로컬 카운터.

### 11-2. 사용자 사전 자동 편입
- 이미 등록된 **습관명·루틴명·폴더명·목표명**을 트리거 사전에 실시간 반영.
- 효과: "물 마시기 했어" → 등록된 습관과 정확히 대조되어 `habit.check`로. 신규 습관과 체크를 구분.
- 앱 데이터가 곧 사전이므로 별도 관리 부담이 없다.

### 11-3. 퍼지 매칭 (STT 오차 흡수)
- 키워드 매칭 시 **편집거리(Levenshtein) ≤ 1~2** 허용으로 근접 오인식을 잡음.
- "치가→치과", "미링→미팅" 류. 단, 짧은 단어(2글자 이하)는 거리 0만 허용(오버매칭 방지).

### 11-4. 확정 스낵바의 "다르게 담기" 칩
- 되묻지는 않되, 실행 직후 스낵바에 재분류 칩 1~2개: `[일정으로]` `[매트릭스로]`.
- 오분류를 **대화 없이 한 탭**으로 교정 → 체감 정확도가 급상승. 이 탭이 곧 11-1의 학습 신호가 된다.

### 11-5. 본인 말투 회귀 코퍼스
- 8장 30문장을 **본인이 실제 쓰는 말투 100~200문장**으로 확장해 회귀 테스트로 고정.
- "완벽에 가까움"을 감이 아니라 **통과율 %로 지키는 방어선**. 사전을 손볼 때마다 이 코퍼스로 회귀 검증.

> 11-1·11-2가 핵심: **AI 없이도 쓸수록 똑똑해지는** 구조. 완벽주의와 궁합이 맞는 이유다.

## 13. 실사용 말투 대응 (사용자 코퍼스 기반 · §11-5)

실제 사용자 말투를 회귀 코퍼스(`test/voice/ch11_my_corpus_test.dart`, 40+문장)로 고정했다.
사용자 말투 패턴: **①조사 생략 ②~날 접미사 ③명령어미 ~줘/~놔/~바 ④한 문장 명령 2개
⑤과거형=기록·미래형=등록 ⑥금액은 만원 단위**.

### 13-1. 이번에 반영(범위 내, 콜로케이션·사전 하드닝)
- **~날 접미사**: `N일날 / N월 N일날 / 광복절날 / 요일날` 파싱.
- **연도**: `29년→2029, 내년/올해/작년`. 명시 연도는 롤오버 안 함.
- **상대일 축약**: `낼(=내일), 낼모레(=모레)`.
- **월 오프셋**: `다음달/담달/이번달 + N일`.
- **명사형 과거(⑤)**: `주문넣음/퇴근찍음/결제함/출발함/나감/들어옴` → 기록(D).
- **담기·기입 동사(③)**: `적어줘/추가해줘/넣어놔/걸어줘/띄워줘/등록`. 날짜와 함께면 일정(C),
  날짜 없으면 할일(A)로. 제목에서는 걷어냄.
- **습관 체크**: `체크(해줘)/다 채웠어/성공/틱` → habit.check(E). 등록 습관명 대조와 병행.
- **양력 공휴일**: 신정·삼일절·어린이날·현충일·제헌절·광복절·개천절·한글날·크리스마스.
- **금액 슬롯(⑥)**: `원`으로 끝나는 표현(`9만원=90000·15만 오천원=155000·만이천원=12000`)을
  `amount`(원)로 뽑고 제목에서 제거(`KoMoneyParser`). "병원" 같은 오검출은 방지.

### 13-2. 로드맵(미지원 → 지금은 안전망 A/보류함/기록으로 안착)
우선순위 순. 전부 **말은 버리지 않되**(§8 안전망) 정밀도만 미달인 상태다.

1. **bare수 금액** — `원` 없이 문맥상 만원단위(`월세 60`, `적금 200`). 문맥 판별 필요. *지금은 미추출.*
2. **복합 명령(④)** — `그리고/아,/거기에/~하고` 접속어로 발화를 분할해 다중 실행. *지금은 앞 동작만.*
3. **수정·삭제·취소(§12)** — `미뤄줘/지워줘/빼줘/취소/말고 8만원`. 파괴적이라 별도 설계 필요
   (비파괴 취소선 우선 검토). ⚠️ *지금은 삭제 발화가 오히려 새 항목을 생성할 수 있음.*
4. **음력 명절 + 다일 범위** — `추석/설날 + 연휴 내내`, `1일부터 4일까지`, `하루종일`.
5. **반복·알림** — `매주 반복`, `알림 한시간 전`.
6. **질문 누수** — `제헌절 쉬는날 맞나`, `독서 몇번 했지` → 지금은 A/보류함. 질문 의도 감지 필요.
7. **주차 표현** — `8월 첫째주 금요일`.
8. **퍼지 매칭(§11-3)** — STT 오타 `돗수→도수`, `너어놔→넣어놔`. 편집거리 ≤1~2.

### 라우팅 단정 규칙(커밋8 코퍼스 활성화 시 확정)
- §8 표의 `route` 는 "인텐트 기본 지점"이다. **확정(S≥3, D≥1)일 때만** 그 지점으로 간다.
- 임계 미달이면 §2 대로 **빠른담기(A)**, 미인식(S==0)이면 **보류함**. "금요일에 장보기"(§8 "C 또는 A")·
  "파란색 그거 처리"(애매)는 A 로 안착하는 게 정답 — 인텐트 자체는 최고점이라 §8 기대치와 같다.
- co 트리거는 primary 가 잡힌 뒤에만 가점(오검출 방지). weak 신호(예: "처리")는 +1 로 S>0 을
  만들어 미인식(보류함)이 아니라 애매(A)로 떨어뜨린다.
- habit.check 는 §11-2 등록 습관명 대조 시 log.now(pastTense)보다 앞서게 강신호+키워드로 얹는다.

### 확정 설계 결정(구현 중 굳힌 것)
- 파이프라인 로직은 순수 Dart(프레임워크 비의존)로 유지 → 빠른 단위 테스트.
- 분류기는 **정규화 원문**에서 키워드 매칭(파서가 "오늘"을 날짜로 잘라내도 goal.today 단서 유지). 제목은 SlotExtractor 가 `stripFrom` 으로 분리.
- 오전/오후 표기 없는 1~6시는 오후로 보정("3시"→15:00, 상수 `bareHourPmMax`).
- 애매시각(아침 등) 단독은 시각으로 안 씀 — "H시" 앞 수식어일 때만(오검출 방지).
- 과거 시제는 사전 목록 기반("막혔어/못하겠어" 오검출 방지).
